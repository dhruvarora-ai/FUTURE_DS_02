# Customer Retention & Churn Analysis

End-to-end churn and retention analysis for a telecom customer base, built with **Python, Excel, and Power BI**. The project identifies churn patterns, retention drivers, and customer lifetime value trends, and delivers a set of concrete, prioritized recommendations to reduce churn.

**Dataset:** [Telco Customer Churn](https://www.kaggle.com/datasets/blastchar/telco-customer-churn) (Kaggle, blastchar) — 7,043 customers, one row per customer.

---

## Key Results

| Metric | Value |
|---|---|
| Overall churn rate | 26.5% |
| Overall retention rate | 73.5% |
| Avg tenure — churned customers | 18.0 months |
| Avg tenure — retained customers | 37.6 months |
| Avg monthly charges — churned | £74.44 |
| Avg monthly charges — retained | £61.27 |
| Annual revenue at risk (churned base) | ~£1.67M (estimated) |
| Month-to-month contract churn rate | 42.7% |
| Two-year contract churn rate | 2.8% |
| High-risk segment size (MTM + ≤12mo tenure + 0 add-ons) | 895 customers, 43.9% churn |

**Top churn drivers identified:** contract type (15x gap between Month-to-month and Two-year), payment method (Electronic check churns 2.7x more than autopay), internet service type (Fiber optic churns 2.2x more than DSL), and add-on service adoption (5-6 services churn under 13% vs 21-46% for 0-1 services).

## Methodology

### 1. Data Cleaning (`02_clean.py`)
- Fixed `TotalCharges` (stored as text with 11 blank values, all at `tenure = 0`; imputed as 0 rather than dropped)
- Mapped `SeniorCitizen` 0/1 → No/Yes for readability; added a numeric `ChurnFlag` for modeling/DAX
- Verified no duplicate customers and no other missing values

### 2. Feature Engineering
- **Tenure cohorts**: 0-6, 6-12, 12-24, 24-48, 48-72 months
- **ServiceCount**: number of add-on services subscribed (0-6)
- **Risk flags**: `IsMonthToMonth`, `IsAutoPay`, `IsElectronicCheck`
- **CLV proxies**: `CLV_ToDate` (actual `TotalCharges`) and `CLV_ProjectedAnnual` (`MonthlyCharges × 12` — a simple run-rate estimate, not a discounted/probabilistic CLV model)

### 3. Retention Curve Analysis
This dataset is a **single snapshot with no signup date** — there's no way to build a true calendar-based cohort. Two standard workarounds were used instead:
- **Tenure-based cohorts** (grouping by months-on-book rather than join date)
- **Kaplan-Meier survival analysis** (`lifelines` library), treating `tenure` as duration and `Churn` as the event indicator — the standard technique for reconstructing a genuine retention curve from cross-sectional data

### 4. Tools
- **Python** (Pandas, NumPy, Matplotlib, Seaborn, lifelines) — cleaning, feature engineering, churn-driver analysis, survival modeling
- **Excel** (openpyxl, formula-driven — `SUMIFS`/`COUNTIFS`/`AVERAGEIFS`, zero hardcoded results, zero formula errors on recalculation) — cohort/retention workbook
- **Power BI** — interactive dashboard on a single-fact star schema (`Fact_Customer` + 2 sort-order lookup tables), with a dedicated DAX measures library

## Recommendations Summary

1. **Contract migration** — incentivize Month-to-month customers to move to annual/two-year terms (highest-leverage lever: 15x churn-rate gap)
2. **Early-tenure onboarding** — build a structured 0-6 month engagement program (52.9% of all churn happens in this window)
3. **Autopay conversion** — migrate Electronic check payers to automatic payment methods
4. **Service bundling** — promote add-on adoption to low-adoption/new customers
5. **Fiber optic service review** — investigate the elevated churn rate on the premium internet product
6. **High-risk customer list** — maintain a standing retention call-list for the ~895-customer high-risk segment
7. **Data infrastructure** — capture true signup dates and churn-reason data going forward, to enable calendar-based cohorts and root-cause analysis in future iterations

Full detail and supporting charts for each recommendation are in `Customer_Retention_Churn_Report.docx`.

## Limitations & Disclosures

- **No signup date**: cohorts are tenure-based, not calendar-based (see Methodology above)
- **CLV_ProjectedAnnual** is a simple run-rate proxy (`MonthlyCharges × 12`), not a discounted or probability-weighted CLV model
- **Churn drivers are statistical associations, not proven causal relationships** — e.g., Fiber optic's higher churn could reflect service quality, price sensitivity, competitive pressure, or unmeasured customer characteristics
- **No churn-reason/exit-survey data** exists in the source, limiting root-cause certainty
- Demographic churn differences (senior citizen, partner/dependents status) are useful for targeting but are not necessarily causal levers
